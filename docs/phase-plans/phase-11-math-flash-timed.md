## 1. 目标

把算术闪卡从「每关 10 题、按错题数评星、带困难模式」改成：

- **全量随机出完**：每关**教材表全量**随机洗牌后一张不漏出完
  （L1/L2 = **66 张**、L3/L4 = **45 张**，口径见 §2）
- **计时评星**：整局总耗时决定星级，**阈值按题量换算**（每题 2.0s→三星 / 3.33s→二星）
  - L1/L2（66 张）：≤ 132 秒 → ★★★，≤ 220 秒 → ★★，其它 → ★
  - L3/L4（45 张）：≤ 90 秒 → ★★★，≤ 150 秒 → ★★，其它 → ★
- **移除困难模式**：不再有每题 5 秒倒计时

## 2. 题量口径（2026-11-08 修正，主人指正）

> **⚠️ 本节已被主人指正过一次。** 初版我按**现有代码的题池条件**（`a<=9 && b<=9`）算出"四关各 45 张"，那是错的 —— 那不是教材表。
> 正确口径是**人教版一年级上册口算表原样**（含 0），10 以内加法/减法是 **66 张**，不是 45 张。

### 2.1 四张教材表的确切结构

| 关卡 | 教材表 | 算式结构 | 题数 |
|---|---|---|---|
| L1 | 10 以内加法表 | `a,b ∈ [0,10]`，`a+b ≤ 10` | **66** |
| L2 | 10 以内减法表 | `0 ≤ b ≤ a ≤ 10` | **66** |
| L3 | 20 以内进位加法表 | `a,b ∈ [1,9]`，`10 ≤ a+b ≤ 18` | **45** |
| L4 | 20 以内退位减法表 | `a ∈ [10,18]`，`b ∈ [1,9]`，`得数 ∈ [1,9]` | **45** |

L3/L4 的结构与教材口诀表逐条对齐（已验证）：
- L3 按和分组：和=10 有 9 个、11 有 8 个 … 18 有 1 个（教材：9+1=10, 8+2=10 … 1+9=10, 9+2=11 …）
- L4 按得数组：得=1 有 1 个、2 有 2 个 … 9 有 9 个（教材：10-1=9, 11-2=9 … 18-9=9）

### 2.2 为什么不能直接套用固定 90s/150s

**66 张 ÷ 90 秒 = 每题 1.36 秒，扣掉 0.6 秒反馈动画后只剩 0.76 秒净思考。**
一年级孩子读题 + 心算 + 点选项至少 1.5 秒 → **L1/L2 在固定 90s 门下永远拿不到三星**。

| 关卡 | 题数 | 90s 内每题 | 扣 0.6s 反馈后净思考 | 150s 内净思考 |
|---|---|---|---|---|
| L1 / L2 | 66 | 1.36s | **0.76s ❌ 不可达** | 1.67s |
| L3 / L4 | 45 | 2.00s | 1.40s ✅ | 2.73s |

### 2.3 采用的方案（主人 2026-11-08 拍板：严格 66 张）

**严格按教材表出满 66 张（含 0 的送分题也出）。**

| 关卡 | 题数 | 三星线 | 二星线 | 每题（毛/净） |
|---|---|---|---|---|
| L1 10以内加法 | **66** | **132s**（2分12秒） | **220s**（3分40秒） | 2.0s / 1.4s ｜ 3.33s / 2.73s |
| L2 10以内减法 | **66** | **132s** | **220s** | 同上 |
| L3 20以内进位加法 | **45** | **90s**（1分30秒） | **150s**（2分30秒） | 2.0s / 1.4s ｜ 3.33s / 2.73s |
| L4 20以内减法 | **45** | **90s** | **150s** | 同上 |

**阈值口径：按每题答题节奏恒定换算，不是固定 90/150。**

```
三星线 = 题数 × 2000ms      二星线 = 题数 × 3333ms
L1/L2 = 66 × 2000 = 132000ms (132s)    L3/L4 = 45 × 2000 = 90000ms (90s)
L1/L2 = 66 × 3333 = 219978ms (≈220s)   L3/L4 = 45 × 3333 = 149985ms (≈150s)
```

> **用整数毫秒常量（2000 / 3333），不用浮点秒（2.0 / 3.33）。**
> 浮点会让边界判定出歧义：`66 × 3.33 = 219.78s`，写"220 秒"则 219979ms 该判 1 星还是 2 星说不清；
> 用 `3333ms/题` 则阈值恒为整数毫秒，边界唯一可测（实测：149985ms → 2 星，149986ms → 1 星）。

这样做的理由：
1. **每关的"答题节奏"完全一致** —— 孩子在四关拿到同样的星，意味着"算得快"，而不是"这张表短"
2. 66 张 ÷ 90 秒 = 净思考仅 0.76 秒，**一年级孩子做不到** → 固定 90s 会让 L1/L2 永远拿不到三星。缩放到 132s 后净思考回到 1.4 秒，与 L3/L4 同档
3. **主人给的 90s/150s 原样落在 45 张的两个关上**（进位/退位表本来就是 45 小题，90 ÷ 45 = 2.0 秒/题）
4. 一局时长：L1/L2 约 2.8 分钟，L3/L4 约 1.9 分钟

> ⚠️ **代价（明说）**：L1/L2 的"1分半三星"变成"2分12秒三星"。如果想在选关页显示统一口径的目标时间，就得显示每关各自的数字（见 §4.1）。

### 2.4 严格 66 张带来的三个连带影响

| # | 影响 | 处理 |
|---|---|---|
| a | **答案范围变了**：L1/L2 变成 `0..10`（含 `0+0=0`、`5-0=5`、`3-3=0`） | `LEVELS` 的 minAnswer/maxAnswer 必须改（见 §5.1b）。已验证：四关每一个答案都还能凑满 4 个不重复干扰项 |
| b | **一局 2.8 分钟**（原 10 题约 30 秒） | 见 §7 R1（注意力风险）+ §4.1（选关页显示本关目标时间，让孩子有预期） |
| c | **星级文案不能再写死"1分半"** | 标题按星级走（"太快啦！/稳稳的！/完成啦！"），不出现秒数；秒数只在选关页和完成面板按本关实际值显示 |

| 关卡 | 题数 | ≤ 三星线 | ≤ 二星线 | 其它 |

| L1 / L2 | 66 | ≤ 132s | ≤ 220s | 1 星 |

## 5. 引擎改动（`current/engine/math-flash.js`）

### 5.1 题池重建

当前 `createQuestion()` 每次调用都**重新穷举全池 + 随机抽一张**，导致：
1. 同一题可能重复出现（如 `10+10` 可能出两次）
2. 无法保证"全部出完"

改为：启动时构建一次**去重的完整卡片池**（L1/L2 = 66 张，L3/L4 = 45 张）→ 洗牌 → 依次发牌。

```js
// 每关固定 66 / 45 张唯一知识点卡（教材表全量）
function buildDeck(size) {
  const level = LEVELS[size];
  const seen = new Set();
  const cards = [];
  for (let a = 1; a <= 20; a++) {
    for (let b = 1; b <= 10; b++) {
      const answer = level.op === "+" ? a + b : a - b;
      if (!isValidCard(size, a, b, answer)) continue;
      const key = `${a}-${b}`;           // 去重键
      if (seen.has(key)) continue;
      seen.add(key);
      cards.push({ a, b, op: level.op, answer });
    }
  }
  return shuffle(cards);
}
```

各关合法性条件（在现有 `createQuestion` 基础上收紧，去掉 0 边角与重复）：

| 关卡 | 条件 | 说明 | 题数 |
|---|---|---|---|
| L1 | `a>=0 && b>=0 && a<=10 && b<=10 && a+b<=10` | 10 以内加法表（教材原样，含 `0+0`/`10+0` 等 21 张含 0 的） | **66** |
| L2 | `a>=0 && b>=0 && b<=a && a<=10` | 10 以内减法表（教材原样，含 `a-0` 11 张 + `a-a` 得 0 的 11 张） | **66** |
| L3 | `a<=9 && b<=9 && a+b>=10 && a+b<=18` | 20 以内进位加法表（教材原样，含和=10 那 9 张） | **45** |
| L4 | `a>=10 && a<=18 && b>=1 && b<=9 && a-b>=1 && a-b<=9` | 20 以内退位减法表（教材原样，含 `10-1` 那 9 张） | **45** |

> **与现有代码的差异（全部按教材表重写）**：
> - 现码 L1 `a<=9 && b<=9` → 漏掉 `10+x`/`x+10` 共 21 张
> - 现码 L2 `a>=2` → 漏掉 `1-b` 共 11 张
> - 现码 L3 `a<=10 && answer>=11` → 多出 `10+1..10+9` 和 `10+10`，共 55 张
> - 现码 L4 `a>=11` → 漏掉 `10-1..10-9`；且 `a<=20` 多出 20 减几那 9 张
>
> **⚠️ 送分题说明（主人拍板"严格 66 张"，这些题会出给孩子）**：
> - L1 的 21 张含 0 题（`0+0=0`、`0+5=5`、`5+0=5`…）
> - L2 的 22 张（`5-0=5`、`3-3=0`…）
> - 一年级还没学到"0 的认识"（第二单元），这些题孩子可能答不出 → 答错不扣星但会计入正确率，属可接受的代价
> - **若实测发现孩子被这些题卡住**，可加一个"跳过含 0 题"的开关（引擎里一个常量即可），但默认按主人的决定出满

### 5.1b `LEVELS` 的 minAnswer / maxAnswer 必须同步改

题池调整后答案范围边界变了，**不改会导致 `createOptions()` 造出越界干扰项**：

| size | 字段 | 现值 | 新值 | 原因 |
|---|---|---|---|---|
| 3 (L1) | minAnswer | 2 | **0** | 含 `0+0=0`、`0+5=5` |
| 3 (L1) | maxAnswer | 10 | **10 不变** | `10+0=10` / `0+10=10` |
| 4 (L2) | minAnswer | 0 | **0 不变** | 含 `a-a=0`（`3-3=0`） |
| 4 (L2) | maxAnswer | 9 | **10** | 含 `10-0=10` |
| 5 (L3) | minAnswer | 11 | **10** | 教材表含和=10 那 9 张（`9+1=10`、`8+2=10`…） |
| 5 (L3) | maxAnswer | 20 | **18** | 教材表最大是 `9+9=18`，去掉 `10+10=20` |
| 6 (L4) | minAnswer | 2 | **1** | 教材表含 `10-9=1` |
| 6 (L4) | maxAnswer | 19 | **9** | 20 以内退位减法得数最大 9（`10-1=9`） |

改完后每关答案区间（**已用脚本验证**）：
- L1 `0..10` / L2 `0..10` / L3 `10..18` / L4 `1..9`

`createOptions()` 用 `level.minAnswer/maxAnswer` 过滤干扰项。**已验证四关的每一个答案都能凑满 4 个不重复选项**（L2/L4 最窄：答案=1 → 干扰项 2,3,4；答案=9 → 干扰项 8,7,6），**选项生成逻辑本身不用改**。

### 5.1c 去重后与教材口算表的对应（复核结论）

四关题量逐条对齐人教版一年级上册口算表（L1/L2 = 66，L3/L4 = 45）：

| 关卡 | 教材表 | 结构 | 小题数 |
|---|---|---|---|
| L1 | 10 以内加法表 | 原样（含 21 张含 0 的） | **66** |
| L2 | 10 以内减法表 | 原样（含 22 张 `a-0` / `a-a`） | **66** |
| L3 | 20 以内进位加法表 | 原样，含和=10 那 9 张 | 45 |
| L4 | 20 以内退位减法表 | 原样，含 `10-1` 那 9 张 | 45 |

已验证 L3 按和分组为 9/8/7/6/5/4/3/2/1（和=10..18），L4 按得数组为 1/2/3/4/5/6/7/8/9（得=1..9）—— 与教材口诀表结构完全一致。

### 5.2 session 结构

```js
{
  size, deck: [...66 或 45 张], cursor: 0, correctCount: 0, wrongCount: 0,
  locked: false, current: null, options: []
}
```

- `startQuestion()`：从 `deck[cursor]` 取题，不再调 `createQuestion()`
- `nextQuestion()`：边界从 `cursor >= 10` 改为 `cursor >= session.deck.length`
- `submitAnswer()`：边界同步改
- `submitTimeout()`：**删除**（困难模式移除）
- `startQuestion()` / `nextQuestion()` / `submitAnswer()` 的 `cursor >= 10` 边界 → `cursor >= session.deck.length`
- `calcStars(wrongCount)` → **新增** `calcStarsByTime(elapsedMs, deckSize)`（3/2/1，不返回 0；阈值 = deckSize × 每题秒数）
- `calcTrophy(wrongCount)` → **新增** `calcTrophyByStars(stars)
- **新增** `STAR_MS_PER_QUESTION = { three: 2000, two: 3333 }` 与 `getStarThresholds(deckSize)` → `{ three: deckSize*2000, two: deckSize*3333 }`
- `calcTitle(stars)` → 文案改为 "太快啦！/ 稳稳的！/ 完成啦！"

> 命名原则（skill 明确要求）：改共享函数前先查调用方；新口径**新增专用函数**，不改 `calcStarCount` / `calcTrophyTier`（其他 7 个游戏在用）。

### 5.3 选项干扰项

`createOptions()` 现有逻辑（用 answer ± 偏移量造干扰项）**可沿用**，但需检查边界：L1 答案范围 2..10、L4 答案范围 2..19，偏移后越界会被 `minAnswer/maxAnswer` 过滤掉，然后从 remaining 补齐。现有代码已处理，**不改**。

## 9. 移动端测试脚本改造（R5 展开）

当前脚本对每个 size 走：点难度 → 等 500ms → 测量 gameplay → 手动显示 complete panel → 测量。

算术闪卡的问题：**gameplay 阶段只等 500ms**，本来就没真打 10 题（脚本只测布局，不测玩法）。所以**脚本实际不会被打到 45 题**——它只做布局测量。

需要改的只有：
- 脚本 `GAME_SIZES['open-math-flash'] = [3,4,5,6]` —— **保持不变**（4 个有效关卡正好对上）
- 脚本手动填的 `complete-stats` 文案 `'用时 00:42 · 成功率 8 / 8（100%）'` —— 可保留（它是布局探针，不是真数据）
- **但**完成面板真实文案变成"答对 N / 66"后，若比探针文案长，需在脚本里同步成最长形态（`答对 66 / 66（100%）`），确保布局断言覆盖真实文案
